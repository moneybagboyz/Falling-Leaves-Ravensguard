## Found by the lead (golden-hash bisect)
- **Chunk tiles name build pieces by palette number, and the palette is the piece ids sorted alphabetically (`PiecePalette`).** Adding any build piece (onboarding added `notice_board`, `training_dummy` and `yard_bench`) renumbers every piece after it.
  - This changed the golden chunk hashes for seeds 1 and 1234 (bisected to b14ed86; reverting the three pieces restores them).
  - Worse, chunk snapshots in saves store tile codes without the palette, so after a content update or a mod that adds a piece, every visited chunk would show the wrong furniture. That breaks plan §2.2 ("content patches and mods never silently change places the player has already been").
  - Fix: store the palette id list with the chunk snapshots (once per save section) and remap numbers on load; compute chunk content hashes over piece ids rather than numbers, so adding an unrelated piece doesn't change any world; add a test that adding a piece leaves saved and freshly generated chunks unchanged; bump the save format with a migration step.
