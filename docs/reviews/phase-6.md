# Phase 6 code and bug check

Reviewed at db10bd7 (every Phase 6 step merged: society, factions, rule, faith and family): the code added or changed since b5d9234 closed Phase 5 (`git diff --stat b5d9234..db10bd7`: 592 files, about 53,600 lines added). The review covers the simulation and the places where the game wires it. It follows plan §6, "Code and bug check". It records findings only: nothing in `src/` was changed. Each finding was checked against the code. One (S1) was also confirmed by a throwaway test that failed on db10bd7; the test was then deleted, and its repro is below. Confidence is given per finding: **high** means read and traced end to end, or tested; **medium** means the mechanism was read but how often it happens in play was not measured.

The open list (`docs/reviews/phase-6.md`) was read first. Items it already records as "not built" are not repeated here, unless the gap breaks a part that *is* built (S4, S6, S11).

### Notes
- **The hero's id 0** (S6, S7, S8) still causes bugs, as the open list warned (Phase 4 S13, the A3 note). Other modules handle it correctly: bondage (`Slavery.Nobody`), D2 (`Opinions.K`), crime (`-1` for an unknown perpetrator), `Road` (`IsHero`). The failures are where `EntityId.None` or `0` is read as "nobody". A grep of the new modules for `== EntityId.None`, `!= EntityId.None` and `== 0` on person ids found these three. The others were checked and are places, entries or deliberate. A non-zero hero id in a later save step would remove the whole class of bug.
- **S1 and S15** are the Phase 5 S1 lesson again: a test of "resume" has to rebuild the world the way a real load does.
- **S2 and S3** together mean that a kin kidnapping ends in a free release after two days, and a rescue contract posted for it pays out.

## Checked and found clean
- **Determinism:** no `float`, `MathF`, `Math.Sin`/`Pow`/`Exp`, `DateTime`, `Stopwatch`, unseeded `Random` or `Parallel` in the new sim code; the doubles are listed in S16. The books are `SortedDictionary`/`SortedSet` or lists in id order. The hash sets in the new modules are used for lookup only. Two plain `Dictionary` iterations feed results, `FaithEngine.Season`'s `taken` (the bishops' stipends) and `FireWorld.HourStep`'s `boxes`. Both are filled once in key order with no removals, so they iterate in insertion order; this is deterministic in practice but rests on an implementation detail. Every draw is keyed on ids and game time. Stream and draw-index pairs within each new module do not collide (Diplomacy 0x671 draws 0 to 4, Relics 0x656 draws 0 to 2 on separate key spaces, Bondage 0x631 draws 1000 and up against 100 and up, 0x632 draws 0 to 2). The live hash trail is unchanged (Phase 5 S1 respected); the Phase 6 hashes join `phase5_trail` only once non-empty.
